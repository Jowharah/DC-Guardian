# DC-GUARDIAN against isolated single-domain monitoring

Generated by `presentation/backend/validation/baseline_comparison.py` on the labelled uncertainty scenarios. Both systems use the same DCG-DECISION-v2 single-event severities, so the comparison isolates the effect of correlation and group severity. A queue is sorted by severity with ties in random order (averaged over 500 orders); an alert is relevant when it contains an event of a labelled incident. Labels were written by the scenario author.

## 1. Held-out test split (24 scenarios, primary result)

| Metric | Isolated single-domain | DC-GUARDIAN (correlated) | Note |
|---|---:|---:|---|
| Alerts shown | 65 | 44 | fewer is better; difference 95% CI -29 to -14 |
| Noise alerts (no incident event) | 23 | 16 | fewer is better |
| Incidents shown whole in one alert | 0 | 11 | of 18 |
| Multi-event incidents shown whole in one alert | 0 | 11 | of 18 |
| Mean alerts per multi-event incident | 2.333 | 1.556 | 1.0 is ideal |
| Top-severity precision | 64% (MEDIUM) | 86% (HIGH) | share of top-level alerts that are incidents |
| Average precision of the queue | 0.659 | 0.742 | higher is better; difference 95% CI 0.021 to 0.179 |
| Alerts reviewed until every incident seen once | 52.124 | 38.584 | fewer is better |
| Alerts reviewed until every incident event seen | 64.542 | 43.370 | fewer is better; difference 95% CI -29.4 to -13.9 |
| Mean queue position where an incident is first seen | 22.501 | 15.387 | lower is better |

Intervals: DC-GUARDIAN minus isolated, bootstrap over scenarios (1000 draws, 20 tie orders each).

## What this shows and what it does not

- **Shows:** on these scenarios, correlation reduces the number of alerts, presents multi-event incidents as one alert instead of fragments, and moves incidents up the review queue, because only linked groups reach HIGH.
- **Does not show:** performance on real site data (the scenarios and topology are synthetic); that severity levels are correct (the scenarios have relatedness labels, not severity labels); or anything about response recommendations, which need a separate user evaluation.
- **Bias:** the scenarios, the labels, the linkage rule and its known-mechanism list come from the same author; the linkage rule was selected on the dev split. No independent labelling round was run (dropped for time).
- **Baseline design:** isolated monitoring here uses DC-GUARDIAN's own single-event policy, which caps single events at MEDIUM. A real single-domain tool might rank differently; the comparison measures the added value of correlation, not of any particular commercial tool.
