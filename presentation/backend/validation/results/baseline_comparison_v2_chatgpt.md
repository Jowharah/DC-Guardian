# DC-GUARDIAN against isolated single-domain monitoring — scenario set v2-chatgpt

Generated by `presentation/backend/validation/baseline_comparison.py` with `--set v2-chatgpt` on the labelled uncertainty scenarios. Both systems use the same DCG-DECISION-v2 single-event severities, so the comparison isolates the effect of correlation and group severity. A queue is sorted by severity with ties in random order (averaged over 500 orders); an alert is relevant when it contains an event of a labelled incident. Scenario set v2, labels: ChatGPT's blind labels of the same pack. Sensitivity check only: a language model's second opinion, not an independent expert.

## What this shows and what it does not

- **Shows:** on these scenarios, correlation reduces the number of alerts, presents multi-event incidents as one alert instead of fragments, and moves incidents up the review queue, because only linked groups reach HIGH.
- **Does not show:** performance on real site data (the scenarios and topology are synthetic); that severity levels are correct (the scenarios have relatedness labels, not severity labels); or anything about response recommendations, which need a separate user evaluation.
- **Bias:** the scenarios, the labels, the linkage rule and its known-mechanism list come from the same author; the linkage rule was selected on the dev split. Independent labels are pending. Here ChatGPT's labels replace the author's, which removes the author from the labels but not from the scenarios or the rule.
- **Baseline design:** isolated monitoring here uses DC-GUARDIAN's own single-event policy, which caps single events at MEDIUM. A real single-domain tool might rank differently; the comparison measures the added value of correlation, not of any particular commercial tool.
